# Риск дистрибуции

Единственный раздел, где риск вообще не про технологию. Бьёт одинаково по Lynx
и по React Native, но входит в решение, потому что меняет вопрос
«выпускать ли Android-приложение вообще» и «от какого юрлица».

## Android Developer Verification — мина 2027

Google переносит верификацию разработчика **на уровень ОС**, на все сертифицированные
устройства. Касается **любого канала установки**, включая RuStore и сайдлоад.

- 30 сентября 2026: Бразилия, Индонезия, Сингапур, Таиланд
- 2027: остальные регионы, включая Россию

RuStore пишет об этом сам и советует своим разработчикам идти регистрироваться
в Google Android Developer Console отдельно.

Публичные разборы **противоречат друг другу** в том, смогут ли разработчики
из подсанкционных стран пройти верификацию вообще: одна формулировка говорит,
что не смогут, другая, что Россия не входит в список исключений, то есть
верификация на российских устройствах будет применяться.

**Это самый непросчитанный риск во всём плане**, и он завязан на ИП в Армении.
Решение по юрлицу стоит подвинуть раньше октября.

## Остальные гейты

| Гейт | Состояние |
|---|---|
| **16 КБ page sizes** (обязательно с 1 ноября 2025, жёсткая отсечка 1 февраля 2027) | **Чисто.** Библиотеки Lynx были невыровнены, issue #1542 закрыт в 3.4.2 (9 октября 2025), Sparkling пинит 3.9.0. Только поднять `com.facebook.fresco:animated-gif` до ≥3.4.0 |
| **targetSdk 36** для новых приложений в 2026 | **Работа на день один.** Шаблон Sparkling везёт `compileSdk = 34`, `targetSdk = 34`, `minSdk = 24`, ABI только `armeabi-v7a` и `arm64-v8a`. Никто этот шаблон не поднимал |
| **Google Play для российского разработчика** | Бесплатное приложение с физическими товарами публиковать и обновлять **можно**. Приостановлены только продавцовские сервисы, платные приложения и IAP |
| **Apple Developer Program** | Enterprise Program для российских компаний закрыта с февраля 2025, регистрации граждан РФ буксуют. Половина плана на iOS зависит не от Lynx, а от армянского юрлица |
| **RuStore** | **Технически не событие.** Требований, специфичных для Lynx, нет: модерация, возрастная маркировка, 64-битные библиотеки, подписанный артефакт. APK Sparkling это просто APK. RuStore Pay для физических товаров не нужен |

## Одно требование, меняющее план пакетов

На устройствах без сервисов Google **FCM не доставляет**. Настоящий канал в России
это **RuStore Universal Push**, а не Firebase. Значит пуш-модуль для этого рынка
выглядит как RuStore плюс APNs.

Это и есть причина, по которой исходный план «портировать `react-native-notify-kit`»
заменён на `lynx-push-ru` внутри `lynx-notify`.

## Не проверено

Является ли RuStore Universal Push сам по себе мульти-провайдерной абстракцией,
маршрутизирующей между FCM, HMS и своим каналом. Если да, наш слой провайдеров
частично лишний. **Выяснить до начала работы над провайдерами.**
