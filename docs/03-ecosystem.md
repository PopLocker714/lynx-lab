# Экосистема: что есть и чего нет

Парадокс: **рельсы достроены, полки пустые.**

Lynx 4.0 (20 июля 2026) привёз полный конвейер нативных библиотек: `lynx.lib.json`,
`create-lynx-library`, `@lynx-js/autolink-codegen`, `@lynx-js/weak-node-api`
(N-API плюс CMake, аналог JSI и Nitro), Gradle-плагины 4.0.1, гем `cocoapods-lynx-library`.

А GitHub code search по `lynx.lib.json` находит **8 репозиториев во всём мире**,
три из них шаблоны ByteDance.

## Что покрыто официально

| Категория | Пакет |
|---|---|
| UI-примитивы | `@lynx-js/lynx-ui`, 20+ headless-компонентов, включая bottom sheet |
| Анимация | `@lynx-js/motion`, порт framer-motion, v0.0.6 |
| Жесты | `@lynx-js/gesture-runtime` |
| Хуки | `@lynx-js/react-use` |
| Тесты | `@lynx-js/testing-environment`, ReactLynx Testing Library, `@lynx-js/node-lynx` |
| Встроенные элементы | `<svg>`, `<image>`, `<video>`, `<webview>`, глобальный `fetch` |

## Дыры, отсортированные по «нужно для реального приложения»

### Ship-blocking, маленькая нативная поверхность

| # | Что | Оценка сложности | Состояние |
|---|---|---|---|
| 1 | **Персистентное KV** (MMKV / AsyncStorage) | 3/10 | **Ничего для ReactLynx.** Движок даёт только `lynx.setSessionStorageItem` (in-memory). Официальный пример заставляет писать модуль самому. `sparkling-storage` умеет только `setItem`/`getItem`, iOS-половина это один протокол, Android незашифрованный SharedPreferences. `lynxjs-mmkv` это заглушка на 113 байт |
| 2 | **Permissions** | 3/10 | Ничего для ReactLynx. Гейтит камеру, геолокацию, уведомления, фото: **зависимость всех остальных модулей** |
| 3 | **Safe area и клавиатура** | 3/10 | Только `@tamer4lynx/tamer-insets` (0.0.5, стухший) и `@sigx/*`. `env(safe-area-inset-*)` **на Android не работает вообще**: ни одна платформенная ветка не заполняет статики |
| 4 | Haptics | 1/10 | `lynx-pulsar` (9 загрузок в месяц), `@tamer4lynx/jiggle` (0.0.1) |
| 5 | Secure storage | 3/10 | `@amritk/lynx-secure-storage`, MIT, ~500 строк. **Форкнуть, не писать** |

### Существенное, средний объём

Файловая система, push, биометрия, нативные пикеры даты, SQLite, кэш картинок,
прикладной WebSocket (`@lynx-js/websocket` 0.0.4 не трогали с 9 марта 2025 и это
только фасад).

### Существенное, но большое или занятое

- **IAP / StoreKit / Play Billing:** **ноль пакетов во всей экосистеме**,
  ни обёртки, ни RevenueCat, ни заглушки. Но для физических товаров не нужно вовсе
- **Аналитика и краши:** Sentry заморожен на `0.1.0-preview.2` с 3 сентября 2025.
  Ни PostHog, ни Amplitude, ни Firebase Analytics, ни AppMetrica
- **Навигация: ЗАНЯТО.** Software Mansion Labs делает `lynx-screens` и прямо пишет,
  что это примитивы под чужую полноценную навигационную библиотеку. **Не переделывать
  примитивы.** Открыт слой JS-навигатора поверх, но сначала написать им
- **Камера, карты:** только `@sigx/*`, многомесячная работа для одного человека
- **Reanimated/Skia-эквиваленты:** самое вероятное место, куда Software Mansion пойдёт дальше

## Кто занимает территорию

- **ByteDance** сам: `tiktok/sparkling` (навигация, storage, media) плюс обещание
  «more device APIs» в роадмапе
- **Software Mansion Labs:** активно делает `lynx-screens`. Пушили в день разведки
- **Callstack:** евангелизм, **ноль кода**. Строка «callstack» не встречается
  в репозитории Sparkling, среди 7 контрибьюторов их нет
- Солисты: SignalX (~100 модулей, но заперты в своём не-React рантайме),
  `@amritk` (5 настоящих autolink-модулей), Tamer4Lynx (стух с мая 2026)

## Сквоттинг имён

Два автора заняли ~85 имён на npm:

- `sultanmyrza` зарезервировал ~70 имён `sparkling-*` 31 мая 2026 пустышками по 1.3 КБ
- `newarch-mansion` занял ~15 имён `lynxjs-*` (mmkv, navigation, reanimated, biometrics…)
  в марте 2025 заглушками по 113 байт

**Практическое следствие:** очевидные имена без скоупа уже разобраны.
Серьёзному участнику нужен свой scope.

## Некодовая дыра

**Нет поддерживаемого индекса экосистемы.** Лучший awesome-список (funcsio) имеет
35 звёзд, не обновлялся четыре месяца и содержит ровно одну стороннюю запись
в разделе тулинга.

Поддерживаемый `awesome-lynx` с таблицами по категориям стоит **дни, а не месяцы**,
и делает автора точкой входа в экосистему, то есть человеком, которого спрашивают
до того, как начать писать модуль. Для набора контрибьюторов это работает лучше
любого README.

## Не проверено

Официальный Discord Lynx не индексируется, поэтому анонсы библиотек, обсуждения RFC
и то, кто там что координирует, остались за кадром. **Перед тем как вкладывать месяцы
в категорию, прочитать историю `#showcase` и `#help`.**
